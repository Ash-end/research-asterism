# Contributing

Useful contributions improve a concrete research decision: a clearer assumption, a counterexample, a better source-support check, a distinguishing design, or a reproducible usability repair. Describe the trigger, current problem, proposed change and evidence.

Use synthetic or explicitly public materials. Remove private project histories, credentials, machine paths and restricted documents. Submit only original content or material with documented compatible rights; external attribution does not grant redistribution permission. Noncommercial source text cannot be copied into this MIT package.

Keep the entrypoint concise and route detailed guidance to references. Do not add fixed paper quotas, novelty scores, universal method rankings, publication guarantees, paid dependencies or mandatory agents. A new instruction should generalize beyond the motivating fixture.

Run `python scripts/validate.py .` and `python -m unittest discover -s tests -v`. Browser changes can also run `node tests/site-check.cjs URL OUTPUT_DIRECTORY` with Playwright and a compatible browser. List actual runs and limitations in the pull request; planned tests are not passes.

For behavior changes, propose frozen raw cases before reading desired answers. Where authorized and available, compare old/new versions with independent contexts and masked balanced ordering. Keep answers, masks and disagreements. An author sanity check is useful but must be labeled as such. Do not infer novelty or correctness from keywords or a structural validator.

Questions and reproducible bugs can go to [GitHub Issues](https://github.com/Ash-end/research-asterism/issues). For sensitive reports follow [SECURITY.md](SECURITY.md). Source boundaries are recorded in [SOURCES.md](SOURCES.md).
